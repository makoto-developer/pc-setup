# macOS開発環境の自動セットアップ

## 原則

- **手順の正はREADME.mdである**。このファイルには進め方(方針)だけを書き、手順そのものは書かない。README.mdを読み、冒頭「セットアップの流れ」の順にセクションを実行する。READMEとこのスキルの内容が食い違う場合はREADMEを優先し、食い違いがあったことをユーザーに報告する。
- 冪等に進める。各手順を実行する前に現在の状態を確認し、すでに済んでいればスキップして「済」と報告する。
  - 確認の例: `brew list <formula>` / `brew list --cask <cask>`、`defaults read <domain> <key>`、`git config --get <key>`、`test -d <dir>`、`ssh -T git@github.com`、`gh auth status`
- 一度に全部やろうとせず、セクション単位で「実行 → 動作確認 → 短く報告」を繰り返す。READMEに動作確認がある手順は必ず動作確認まで行い、失敗したら止めてエラー内容を報告する(成功したことにしない)。
- 途中で中断されても、再度`/setup`を実行すれば状態確認によって続きから再開できるようにふるまう。

## ユーザーに依頼するもの(自動実行しない)

- **対話コマンド**(パスフレーズ入力・ブラウザ認証が必要なもの): `ssh-keygen`、`ssh-add --apple-use-keychain`、`gh auth login`など
  - 「プロンプトで `! <コマンド>` を実行してください」と依頼し、完了を確認してから次へ進む
- **sudoが必要なコマンド**(ファイヤーウォール設定、docker-desktopのインストールなど):
  - sudoのパスワード入力にはターミナル(TTY)が必要で、Claudeからの実行でも`!`実行でも失敗する
  - **ユーザー自身にiTermの別タブを開いて直接実行してもらう**よう、実行するコマンドを提示して依頼し、完了の報告を待ってから次へ進む
- **ブラウザ・GUI操作**: GitHubへの鍵登録(Authentication Key / Signing Key)、PATの生成、itermのprofile import、Xcode・Google Drive・セキュリティソフトのインストール、READMEの「手動で設定するもの」
  - 何をどこでやるかをREADMEから引いて具体的に案内し、完了の返事を待ってから続行する
- **選択が必要な箇所**(例: 「必要であれば入れるアプリ」のうちどれを入れるか)はAskUserQuestionで確認する

## READMEのプレースホルダの扱い

- ssh鍵名の日付部分(例: `id_github_20251006_ed25519`)は実行日の日付(`id_github_YYYYMMDD_ed25519`)に置き換える
- `<<<your name>>>`などのプレースホルダは値をユーザーに確認して埋める

## 仕上げ

- ssh設定の完了後、このリポジトリ(pc-setup)をhttpsでcloneしていた場合はremoteをsshに切り替える
- 最後に「実行した / スキップした(設定済み) / ユーザー対応が残っている」項目のサマリを報告する
